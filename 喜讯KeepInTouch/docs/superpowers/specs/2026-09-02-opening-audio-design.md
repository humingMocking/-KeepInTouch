# 开场音频循环播放设计

## 目标

点击首页信封后立即播放开场音频。音频只需在小程序前台运行时持续循环，不要求切换到后台后继续播放。音频播放失败不能阻断开信动画和请柬页面展示。

## 现状与问题

当前首页使用 `wx.downloadFile` 下载远程 MP3，再调用已不适合该场景的 `wx.playVoice` 播放临时文件。下载、临时文件和播放 API 形成了不必要的链路，也使失败原因难以区分。

## 方案

在 `App.vue` 中使用 `wx.createInnerAudioContext()` 创建全局普通音频实例，并由首页触发播放：

- 设置 `src` 为 `invitationConfig.audio.opening`。
- 设置 `loop = true`，不启用自动播放。
- 在首页信封点击事件 `requestOpen()` 中获取全局实例并调用 `play()`，确保播放由用户手势触发。
- 注册 `onPlay`、`onWaiting`、`onError` 和 `onEnded` 监听，用于诊断播放状态；发生错误时记录日志并提示用户，但继续执行开信动画。
- 音频实例挂载到 App 的全局作用域，首页和相册页面共享同一个实例；页面销毁时不停止音频。
- 小程序结束运行时由系统回收音频实例；不配置后台播放能力，因此小程序进入后台后不要求继续播放。

删除现有 `wx.downloadFile`、`wx.playVoice` 及临时文件缓存逻辑，保留音频 URL 配置在 `src/config/invitation.js` 中。

## 数据流

1. 小程序启动时初始化全局音频上下文并绑定音频地址。
2. 用户点击信封。
3. 首页 `requestOpen()` 获取全局音频实例并调用 `play()`，同时启动既有开信动画。
4. 音频自然结束后由 `loop` 自动从头播放。
5. 页面切换时继续使用同一个全局音频实例。

## 错误处理

- 音频地址为空或当前运行端不支持 `createInnerAudioContext` 时跳过播放，并保留可诊断日志。
- `onError` 记录错误码、错误消息和音频地址，并显示“音频播放失败，请重试”的非阻塞提示。
- 播放失败不回滚 `opened` 或 `opening` 状态。
- 如果微信开发者工具提示远程音频域名不在合法域名列表，需在微信公众平台配置该 HTTPS 域名；代码不新增服务端代理。

## 验证

- 运行项目编译检查，确认 Vue/uni-app 语法无误。
- 静态检查确认旧的 `downloadFile` 和 `playVoice` 音频链路已移除。
- 在微信开发者工具中点击信封，确认音频开始播放且开信动画正常。
- 等待音频结束，确认自动循环。
- 切换到相册页面并返回，确认全局音频仍持续循环。
- 将音频地址配置为不可用地址，确认错误日志和提示出现，且页面仍能打开。
