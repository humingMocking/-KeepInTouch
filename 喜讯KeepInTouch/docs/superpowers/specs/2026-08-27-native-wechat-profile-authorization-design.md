# 微信原生资料授权打开请柬设计

## 目标

点击首页信封时，不再展示页面内自定义头像昵称填写弹层，而是调用微信小程序原生用户资料授权弹窗。授权成功后缓存访客资料、打开请柬并继续上报访问记录；用户拒绝授权时保持在封面页。

## 范围

- 移除首页的 `showProfilePrompt` 蒙层、头像选择按钮、昵称输入框和相关样式。
- 将信封点击流程改为先检查本地缓存；无缓存时调用 `wx.getUserProfile`。
- 使用微信返回的 `userInfo.nickName` 和 `userInfo.avatarUrl` 作为访客资料来源。
- 让访客服务兼容微信返回的远程头像 URL，下载后转为 base64 再缓存与上报。
- 授权失败或用户取消时给出轻提示，不打开请柬。

## 页面流程

1. 用户点击封面信封。
2. 页面检查本地是否已有完整访客资料缓存。
3. 有缓存时直接打开请柬并上报。
4. 无缓存时调用 `wx.getUserProfile({ desc: '用于确认请柬已送达' })`。
5. 授权成功后缓存昵称和头像，执行信封打开动画，进入请柬页面。
6. 授权失败时显示提示并停留封面。

## 服务适配

`src/services/visitor.js` 继续保持“缓存资料”和“上报访问记录”两个职责。`cacheVisitorProfile` 接收昵称和头像地址后，先尝试将头像源转为 base64：本地临时文件、data URL 维持现有处理；远程 HTTP/HTTPS 头像通过微信下载接口获取临时文件，再复用现有读取逻辑。缓存结构不变，云函数字段不变。

## 错误处理

- 没有微信运行环境或 `wx.getUserProfile` 不可用时，显示“当前环境无法获取微信资料”。
- 用户拒绝授权或授权失败时，显示“需要授权后打开请柬”。
- 头像下载、读取或缓存失败时，显示“资料保存失败，请重试”。
- 任何失败都不进入请柬页，避免产生缺少资料的访问记录。

## 非目标

- 不新增备用自定义填写表单。
- 不调整云函数集合、字段或数据库权限。
- 不改动请柬视觉主体、相册页、分享配置或背景音乐逻辑。

## 验收标准

- 首页不再包含自定义头像昵称弹层相关模板和样式。
- 首次点击信封时触发微信原生用户资料授权弹窗。
- 授权成功后请柬正常打开，访客昵称与头像可缓存并上报。
- 再次进入或再次点击信封时，有缓存则不重复弹授权窗。
- 用户拒绝授权时停留在封面页，信封可再次点击重试。
