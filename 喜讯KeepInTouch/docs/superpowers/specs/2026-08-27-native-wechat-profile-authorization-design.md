# 微信原生资料授权打开请柬设计

## 目标

点击首页信封时，先检查本地是否已有完整访客资料。没有有效缓存时，展示头像昵称填写面板，使用微信小程序 `open-type="chooseAvatar"` 和 `input type="nickname"` 采集资料。资料完成后缓存访客资料、打开请柬并继续上报访问记录；用户未完成资料时保持在封面页。

## 范围

- 保留封面上的资料填写面板，面板只在缺少有效缓存时出现。
- 将信封点击流程改为先检查本地缓存；无缓存或缓存为微信默认资料时展示填写面板。
- 使用 `button open-type="chooseAvatar"` 选择头像，使用 `input type="nickname"` 填写昵称。
- 将选择的头像读成 data URL 后缓存并上报。
- 用户未选择头像或未填写昵称时给出轻提示，不打开请柬。

## 页面流程

1. 用户点击封面信封。
2. 页面检查本地是否已有完整访客资料缓存。
3. 有缓存时直接打开请柬并上报。
4. 无有效缓存时展示头像昵称填写面板。
5. 用户选择头像并填写昵称后，缓存昵称和头像，执行信封打开动画，进入请柬页面。
6. 用户未完成资料时显示提示并停留封面。

## 服务适配

`src/services/visitor.js` 继续保持“缓存资料”和“上报访问记录”两个职责。`cacheVisitorProfile` 接收昵称和头像 data URL 后缓存资料。`getCachedVisitorProfile` 必须拒绝缺少昵称、缺少头像、或昵称为 `微信用户` 的旧默认资料。上报访问记录异步执行，不阻塞进入请柬。

## 错误处理

- 用户未选择头像或未填写昵称时，显示“请选择头像并填写你的昵称”。
- 头像读取或缓存失败时，显示“资料保存失败，请重试”。
- 任何失败都不进入请柬页，避免产生缺少资料的访问记录。

## 非目标

- 不使用 `wx.getUserProfile` 作为真实头像昵称来源。
- 不调整云函数集合、字段或数据库权限。
- 不改动请柬视觉主体、相册页、分享配置或背景音乐逻辑。

## 验收标准

- 缺少有效缓存时，首次点击信封展示头像昵称填写面板。
- 授权成功后请柬正常打开，访客昵称与头像可缓存并上报。
- 再次进入或再次点击信封时，有完整缓存则不重复展示填写面板。
- 用户未完成资料时停留在封面页，信封可再次点击重试。
