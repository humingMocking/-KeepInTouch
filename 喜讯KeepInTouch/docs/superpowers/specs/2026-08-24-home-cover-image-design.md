# 小程序首页图片封面设计

## 目标

使用用户提供的 P1 作为小程序首页首屏背景，使用用户提供的 P2 作为透明底信封主体。封面只展示背景和信封，不保留现有标题、说明文字、按钮或 CSS 绘制的信封装饰。

## 资源处理

- P1 保持原始纵向构图，保存至 `static/invitation/`，作为首页封面背景。
- P2 当前棋盘格已写入像素，不是真实透明通道。接入前去除棋盘格并导出带 Alpha 通道的 PNG。
- 信封处理结果应保留纸张、蝴蝶结、刺绣花朵和蕾丝边缘；中央与花边镂空区域应透明，不出现棋盘格残留或明显灰边。
- 原始附件不覆盖，项目内使用语义化文件名保存处理结果。

## 首屏布局

- `.cover` 占满可用首屏，保持现有 `100vh` 页面边界与溢出裁切。
- P1 使用独立的全屏 `<image>` 节点并设置 `mode="aspectFill"`，以兼容微信小程序静态资源打包，不允许出现空白边。
- P2 使用独立 `<image>` 节点，保持原始宽高比。
- 信封宽度采用已确认的方案 A，约为视口宽度的 `58%`。
- 信封以首屏视口为基准水平、垂直居中，不受安全区、隐藏文案或其他占位元素偏移。
- 信封可增加克制的投影以维持与背景的层次，但不增加额外装饰、卡片或文字。

## 交互

- 整个信封图片作为打开入口，并提供足够的点击区域。
- 点击信封继续调用现有 `requestOpen`，显示现有头像与昵称确认面板。
- 用户完成确认后继续执行现有访客记录与内容切换逻辑。
- 删除 CSS 信封、丝带释放和翻盖动画；打开过程仅让图片信封轻微淡出，不模拟拆封结构。
- 连续点击或打开中的点击继续由现有 `opening` 状态防护。

## 页面清理范围

- 删除封面中的 `cover-glow`、英文眉题、标题、副标题、提示文字和“打开请柬”按钮。
- 删除仅服务于 CSS 信封的 `letter`、`paper`、`flap`、`fold`、`ribbon`、`bow` 等节点与样式。
- 保留头像昵称面板、分享生命周期、背景音频、自动滚动和访客记录逻辑。
- 不调整打开后的内容占位页，也不扩展相册或后端功能。

## 兼容与失败处理

- 图片路径使用 uni-app/微信小程序可识别的 `/static/...` 形式。
- 背景加载期间由 `.cover` 提供接近 P1 主色的兜底底色，避免白屏闪烁。
- 信封图片加载失败时页面仍保持背景可见，不显示损坏图片提示文字。
- 透明信封边缘在浅色和深色背景区域都不得出现明显棋盘格或矩形底。

## 验收标准

- 首页首屏只显示 P1 背景和居中的 P2 信封。
- P1 填满竖屏首屏，常见微信小程序屏幕比例下无空白边。
- P2 宽度约为视口的 `58%`，不变形，并以视口中心定位。
- P2 的棋盘格完全移除，镂空区域具有真实透明通道。
- 点击信封可打开现有头像昵称面板，完成确认后可进入现有下一状态。
- 页面不再渲染旧封面文字、按钮、CSS 信封或丝带动画。
- 代码检查通过，且至少对窄屏、标准屏和宽屏三种竖屏尺寸进行视觉验证。
